# FEAT-032: 무드 카테고리 화면 노출

## Problem

2026-11-16 회의록 〈에린〉: "무드 카테고리 보여주기(힙함, 댄디 등)". 지금 앱엔 카테고리로
둘러보는 진입점이 아예 없다 — 예전엔 `/search`에 "무드별" 그리드(6무드 커버)가 있었는데,
FEAT-021(검색을 제품 검색 전용으로 단순화)에서 통째로 빠졌다. 그 뒤로 사용자가 "느낌"을
직접 타이핑하거나 `/promise`의 상황 칩을 고르는 것 말고는 무드를 둘러볼 방법이 없다.

## 조사 — 지금 있는 재료

- **캐논 6축**(`MOODS`, `src/lib/moods.ts`): `clean`(클린 미니멀), `cityboy`(시티보이),
  `street`(스트릿), `amekaji`(아메카지), `classic`(클래식), `soft`(소프트 캐주얼). 각각
  이미지·설명 있고 `/mood/[key]` 상세 페이지로 바로 연결됨.
- **밈/스타일 키워드 묶음**(`QUERY_MAP`, "Layer 2"): 힙하게, 댄디하게, 올드머니, 시크하게,
  테토남, 에겐남, 느좋, 남친룩, 꾸안꾸, 만찢남 — 각각 2~4개 축의 조합으로 이미 매핑돼 있음
  (예: "힙하게" → street+amekaji+cityboy). 회의록이 예로 든 "힙함, 댄디"가 바로 이 목록에
  있는 단어들 — 축 이름보다 사용자가 실제로 쓰는 말에 가까움.
- `/promise`에 이미 "이런 느낌도 돼" 섹션으로 이 묶음 중 일부(꾸안꾸·테토남·느좋·남친룩)가
  칩으로 들어가 있음(FEAT-022) — 패턴 재사용 가능.

## 결정 (2026-11-19, 에린)

- Q2 → 홈 상단(성별 토글 빠지면서 생긴 자리).
- Q3 → 그 자리에서(홈 피드 인플레이스 필터링, FEAT-006 `moodKeys`/`query` 메커니즘 재사용).
- Q1 → 처음엔 B안(밈 어휘: 힙하게·댄디하게·올드머니·시크하게)으로 갔다가, 로컬 확인 중
  "댄디하게/올드머니가 너무 비슷하다", "밈 용어는 어떤 옷이 나올지 예상이 안 된다"는 피드백
  으로 재조정 — **캐논 6축에 1:1 매칭**(사실상 A안)으로 최종 변경. 축이 다르면 사진도 달라서
  구조적으로 안 겹치고, 라벨 자체가 옷차림을 가리켜서 패션 지식 없이도 예측 가능.
  `미니멀(clean)·캐주얼(cityboy)·스트릿(street)·빈티지(amekaji)·댄디(classic)·소프트(soft)`.
- UI도 재조정: 알약 모양 버튼 칩 → **밑줄 텍스트 탭**(`frontend-design` 스킬 — 둥근 배지가
  AI 생성 디자인의 대표 패턴이라는 피드백 반영). "전체" 탭을 라디오처럼 추가해서 "같은 칩
  다시 눌러 해제" 방식 대신 명시적 선택지로 되돌아가게 함. 선택 시 헤더 텍스트("'댄디'" 등)는
  탭의 밑줄이 이미 상태를 보여주므로 생략.

## (아래는 결정 전 조사 — 참고용)

- **Q1. "카테고리"를 뭘로 보여줄지.**
  - **A안**: 캐논 6축 그대로(클린미니멀/시티보이/.../소프트캐주얼) — 각각 `/mood/[key]`로.
    장점: 데이터 구조와 1:1, 추가 설계 없음. 단점: 회의록 예시("힙함","댄디")와 어휘가 다름.
  - **B안**: 밈/스타일 키워드 묶음(힙하게/댄디하게/올드머니/시크하게 등 중 추려서) —
    `/results?q=<키워드>`로. 장점: 회의록 예시와 정확히 일치, 사용자 체감 언어. 단점: 10개
    중 몇 개를 "공식 카테고리"로 노출할지 추려야 함(전부 노출은 너무 많음).
  - **C안**: 둘 다 — 상위 카테고리는 B안 어휘로 보여주고, 탭하면 그 조합에 속한 축들의 사진을
    보여주는 식(사실상 B안 라우팅과 동일, 표현만 "카테고리"로 포장).
- **Q2. 어디에 보여줄지.**
  - 홈 피드 상단에 가로 스크롤 칩(필터처럼 — 누르면 그 카테고리로 홈 피드 자체가 바뀜)
  - `/search`에 "무드별" 섹션 복원(단, FEAT-021에서 "검색은 제품 검색 전용"으로 정리했던
    결정과 상충 — 복원하려면 그 결정도 같이 재검토 필요)
  - 완전히 새 위치(예: 나의 공간, 또는 홈의 별도 섹션)
- **Q3. 탭하면 어떻게 동작할지.** 홈 피드를 그 카테고리로 필터링(제자리 반영) vs
  `/results?q=...`로 이동(검색 결과 화면 재사용).

## Scope(구현, 최종)

- `src/app/page.tsx`: `CATEGORIES`(라벨+무드축 쌍) 6개 + "전체" 버튼을 홈 상단(성별 토글 빠진
  자리)에 밑줄 텍스트 탭 모양(가로 스크롤)으로 추가.
- `src/components/HomeGallery.tsx`: 검색/카테고리 모드일 때 헤더(`'{query}'`) 생략 — 탭의
  밑줄이 이미 선택 상태를 보여줘서 중복.

### 소피 코드리뷰 반영(2026-11-20)

- **P0-1**: `recordSearch(라벨)` → `recordView(cat.mood)`. `recordSearch`가 내부적으로
  `resolveMoods`로 라벨을 다시 해석하는데, "미니멀"/"캐주얼" 등은 `QUERY_MAP`에 없어서
  글자수 기반 폴백으로 떨어져 엉뚱한 축(주로 amekaji)에 점수가 올랐었다. 축을 이미 정확히
  아는 상황이라 추측 없이 그 축 하나를 직접 반영.
- **P1-2**: 카테고리 선택 상태를 `useState`가 아니라 URL(`?mood=`)에 둬서, 상세 → 뒤로가기
  해도 선택이 유지되게 함(`router.replace`, 히스토리는 안 늘림).
- **Q-1**: "필터 vs 정렬" — 필터가 맞는 의도라 `rankPhotos` 정렬 방식에서
  `dominantMood(p.mood_vector) === cat.mood` 기준 실제 필터링으로 변경. 스크롤을 내려도 다른
  무드가 안 섞임.
- **P2-1**: `role="tab"`은 `aria-controls`/`tabpanel`/화살표 키 이동이 따라와야 완성되는데
  없어서, 일반 버튼 묶음(`aria-pressed`)으로 변경.

## Verification (Playwright 실측)

- 탭 7개(전체+6개) 홈 상단 노출, 가로 스크롤 동작.
- "스트릿" 선택 → URL이 `/?mood=street`로 바뀌고 역할=link 카드 12장, 전부 스트릿 축.
- 카드 클릭 → 상세 → 뒤로가기 → URL이 `/?mood=street`로 그대로, "스트릿" 버튼
  `aria-pressed=true` 유지(수정 전엔 "전체"로 리셋됐음).
- `localStorage['mood.affinity.v1']`에서 탭 6개 전부 클릭 시 각 축에 정확히 1씩만 반영(수정
  전엔 amekaji 등으로 쏠렸음).
- "스트릿"/"빈티지" 각각 클릭 → 서로 다른 축 사진으로 필터링, 겹침 12장 중 2장(기존 조합
  방식 대비 크게 감소) — 오버핏 후디·카고팬츠(스트릿) vs 데님재킷·워크부츠(빈티지)로 시각적
  구분됨.
- "전체" 탭 클릭 → 기본 피드로 복귀, "전체"에 활성 스타일.
- 카테고리 선택 중엔 헤더 텍스트 생략 확인.
- `tsc --noEmit`, `npm run build` 통과.
