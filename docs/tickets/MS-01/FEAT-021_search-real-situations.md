# FEAT-021: 검색 화면 — 제품 검색 전용으로 단순화

## Problem(1차 — 폐기)

10/28 회의록 "검색창의 추천/상황별(더미데이터->실데이터로 교체)"를 처음엔 `/search`의
"오늘의 추천"/"상황별" 더미 칩을 `photos.situations` 집계로 바꾸는 작업으로 해석했다.

실제로 돌려보니 상황별 칩("주말카페", "소개팅" 같은 단일 명사)을 그대로 검색어로 던지면,
AI 번역이 스타일을 구분할 정보가 부족해서 대부분 비슷한 결과(`clean`/`classic` 쪽으로 수렴)로
나왔다 — "칩마다 다른 사진이 나와야 하는데 다 똑같다"는 사용자 피드백으로 확인. 애초에 더 구체적인
문구(`/promise`의 OCCASIONS: "첫 소개팅", "퇴근 후 술약속" 등)가 AI 해석에 적합했다.

## Problem(2차 — 실제 작업)

사용자 피드백: "search 자체가 제품명 입력이기 때문에 그런(상황별) 칩들은 다 promise에만
있어야 함". 역할을 다시 명확히 함 — `/search`는 제품 검색 전용, `/promise`가 상황 기반 추천을
전담(이미 FEAT-022에서 처리됨). `/search`에서 "오늘의 추천"·"상황별"·"무드별" 섹션을 전부 제거.

## Scope

- `/search`: 검색 입력창(제품명 검색, placeholder를 "제품명으로 검색해봐"로 변경) + 스크린샷으로
  찾기만 남김. "오늘의 추천"/"상황별"/"무드별" 섹션·관련 상수(`MEME_CHIPS` 등) 전부 제거.

## Verification

- `tsc --noEmit`, `npm run build` 통과.
- 로컬 브라우저로 직접 확인. PR #39.

## 참고

제품 검색 자체(상품명 매칭 → 그 상품 포함된 코디)는 FEAT-023에서 `/results` 레벨 로직으로
구현됨 — `/search` 페이지 자체는 검색어를 넘기기만 하면 된다.
