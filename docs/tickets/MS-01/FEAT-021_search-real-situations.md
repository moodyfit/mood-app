# FEAT-021: 검색 화면 상황별 칩 — 실데이터로 교체

## Problem

10/28 회의록: "검색창의 추천/상황별/무드별(더미데이터->실데이터로 교체)". `/search`의 "오늘의
추천"·"상황별" 칩이 `DAILY`/`SITUATION_CHIPS`라는 하드코딩 상수였다.

## Scope

- `src/lib/photos.ts`에 `topSituations(photos, limit, minCount)` 추가 — `photos.situations`를
  빈도순 집계, `minCount` 미만(샘플 적은 롱테일)은 제외.
- `/search`의 "상황별" 칩을 `topSituations` 결과로 교체.
- "오늘의 추천"도 같은 리스트에서 날짜 기반 로테이션으로 하나 뽑아 통합 — `DAILY` 상수 삭제,
  더미 두 개를 하나의 실데이터 소스로 합침.
- `MEME_CHIPS`(테토남/느좋/남친룩)는 유지 — 밈은 DB 태그가 아니라 트렌드 문구라 실데이터화 대상 아님.
- "무드별"은 손 안 댐 — 이미 `MOODS`(캐논 6축) 기반이라 더미가 아님.

## 실데이터 확인(실행 시점)

전체 120장 모두 `situations` 태깅돼 있음, 고유 태그 8개:
주말카페(70) · 동네(62) · 나들이(53) · 데이트(21) · 출근(14) · 소개팅(11) · 저녁약속(8) · 캠퍼스(1).
`minCount=5`로 캠퍼스(샘플 1장) 제외, 상위 6개 노출.

## Verification

- 로컬 Playwright로 `/search` 렌더 확인: 오늘의 추천(로테이션 1개 + 밈 3개), 상황별(6개) 정상 노출.
- "소개팅" 칩 클릭 → `/results?q=소개팅` 정상 이동, AI 번역 정상(BUG-012 수정 반영 전 main
  기준 — PR #38 머지되면 더 안정적으로 동작).
- `tsc --noEmit`, `npm run build` 통과.
