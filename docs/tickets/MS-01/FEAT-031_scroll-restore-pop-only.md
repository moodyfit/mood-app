# FEAT-031: 스크롤 복원을 "뒤로가기(POP)"일 때만 + 히어로 상태 스냅샷

## Problem

### 1. 복원이 "어떻게 들어왔는지"를 안 봄 (소피 피드백, 2026-11-19, PWA 실기기)

하단 탭으로 화면을 옮길 때마다 스크롤이 이전 위치로 복원되는 게 어색하다. 지금
`useScrollRestore`는 "어떻게 들어왔는지"를 전혀 안 보고, sessionStorage에 저장값이 있으면
무조건 복원한다.

소피 제안:
- 목록 → 상세 → 뒤로가기: 지금처럼 복원
- 하단 탭 이동: 복원 안 함, 맨 위에서 시작
- 새로고침: 맨 위에서 시작

세 번째 항목은 BUG-014(새로고침 스크롤 복원 버그, PR #48)를 "제대로 복원하기"가 아니라
"애초에 복원 시도를 안 하기"로 더 근본적으로 해결한다.

### 2. 히어로 등장/퇴장으로 복귀 시 카드 배열이 바뀌어 보임 (소피 피드백, 2026-11-24, PR #49 후속)

BUG-015(PR #49)로 "뒤로가기 시 피드 순서 유지"는 고쳤지만, 순서 자체가 아니라 **히어로 유무**가
바뀌는 경우를 못 잡는다. 새 사용자가 사진 3장째를 보고 돌아오면 그 사이 취향 점수가 히어로
기준(`HERO_MIN_STRENGTH`)을 처음 넘어서, 맨 위에 히어로(화면 너비를 꽉 채우는 큰 사진)가
새로 생기고 나머지 카드가 한 칸씩 밀려 보인다 — 순서 데이터는 그대로지만 레이아웃이 바뀌어
사용자 눈에는 "배열이 바뀜"으로 보인다.

소피 제안: 순서 스냅샷에 "그 방문에서 히어로를 보여주고 있었는지"도 같이 담아, 돌아온 그
방문에서는 저장된 히어로 유무를 그대로 따른다.

## 기술적 난점

Next.js App Router에는 "이 마운트가 뒤로가기(POP)로 왔는지 탭 클릭(PUSH)으로 왔는지"를 주는
공식 API가 없다. Performance Navigation Timing API(`reload`/`back_forward`/`navigate`)는
풀 페이지 로드 기준이라 클라이언트 사이드 라우트 전환에는 적용 안 됨.

필요한 건 `popstate` 이벤트(브라우저 실제 뒤로가기·forward에서만 발생, `router.push`/`<Link>`
클릭에서는 미발생)를 직접 리스닝해서 "마지막 네비게이션이 POP였는지" 신호를 만드는 것.

## Scope

- 전역에서 한 번 `popstate` 리스너를 달아 "마지막 네비게이션 = POP" 신호를 추적(모듈 스코프
  플래그 또는 작은 전역 훅).
- `useScrollRestore`의 복원 effect가 이 신호를 같이 보게 수정 — POP가 아니면 저장값이 있어도
  `scrollTo`를 아예 시도하지 않는다(= 맨 위에서 시작, 새로고침도 포함).
- 저장(write) 쪽 로직은 그대로 — 어차피 복원 여부만 바뀌는 거라 저장을 막을 이유는 없음.
- 기존 레이스 방지 로직(BUG-004/008/011/014 — restoredRef, 디바운스, pointerup 캡처)이 이
  변경과 안 부딪히는지 하나씩 재확인 필요.
- 영향 범위: `HomeGallery.tsx`, `PhotoGrid.tsx`, `ResultsGrid.tsx` 전부(같은 훅 공유).
- **(신규) 히어로 상태 스냅샷**: `HomeGallery.tsx`의 떠날 때 저장(`writeOrderSnapshot`, PR #49)에
  `heroVisible: boolean`을 같이 담는다. POP로 돌아온 그 한 번의 마운트에서는, 현재 `strength`가
  임계값을 넘겼더라도 스냅샷의 `heroVisible`이 `false`였다면 히어로를 억지로 안 보여주고(= 그
  장을 `rest`에 포함), 반대로 스냅샷이 `true`였는데 지금은 임계값 미달이면 히어로를 그대로
  유지한다 — 왕복 1회 한정(기존 순서 스냅샷과 같은 consume-once 생명주기).
  - 히어로 등장 자체가 거짓이 되면 안 되므로, "새로 홈에 들어올 때(스냅샷 없음)"는 항상 실제
    `strength` 기준으로 판단 — 이번 변경은 "복귀" 케이스에만 적용.

## Verification 기준

- 하단 탭으로 화면 이동 → 맨 위에서 시작(스크롤 복원 안 됨).
- 목록에서 스크롤 내린 뒤 카드 클릭 → 상세 → 뒤로가기 → 그대로 복원(기존 동작 유지).
- 새로고침(어느 스크롤 위치에서든) → 맨 위에서 시작.
- 히어로 없던 상태에서 카드 클릭 → (그 사이 임계값을 넘겨도) 뒤로가기 → 히어로 없이 복귀.
- 히어로 있던 상태에서 카드 클릭 → 뒤로가기 → 히어로 유지.
- `tsc --noEmit`, `npm run build` 통과.
