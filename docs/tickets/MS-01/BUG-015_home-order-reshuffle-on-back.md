# BUG-015: 사진 클릭→뒤로가기 시 카드 배열이 바뀜

## Problem

사용자 피드백: "코디 눌렀다가 뒤로가기 하면, 스크롤 위치는 예전이랑 똑같이 유지되는데 카드
배열 자체가 바뀌어서 예전에 봤던 카드가 안 보인다 — 취향 반영을 위한 장치 때문인 것 같은데
어색하다."

## 원인

`PhotoCard.tsx`의 `up()`이 사진 상세로 이동할 때마다 `recordView(photo.mood_vector)`로
`affinity`(취향 점수)를 갱신한다. `HomeGallery.tsx`의 피드 순서(`ordered`)는 `affinity`가
바뀔 때마다 `useMemo`로 다시 랭킹된다 — 그래서 사진 한 장만 눌러도 그 직후 뒤로가기로 돌아오면
전체 피드 순서가 새로 계산된다. 스크롤 위치(px)는 BUG-004/008/011로 복원되지만, 그 위치에
있던 "카드"는 이미 달라져 있다.

## Fix

"떠나는 순간"의 피드 순서를 `sessionStorage`(`moodfit:home-order`)에 한 번 저장하고,
돌아왔을 때(리마운트) 딱 한 번만 꺼내 쓰고 바로 지운다. 새로 추가된 사진(스냅샷에 없는 id)은
뒤에 덧붙이고, 없어진 사진(현재 `photos`에 없는 id)은 건너뛴다. 취향 반영 자체는 막지 않는다
— 바로 다음 클릭부터는 새로 캡처되므로 탭 세션 전체 동안 순서가 영구 고정되지는 않는다.

쓰는 시점은 `window`의 `pointerup` 캡처 단계(BUG-014와 동일 기법) — `PhotoCard`의
`onPointerUp`이 `recordView`(affinity 갱신)와 `router.push`를 부르기 전에 먼저 실행되므로,
클릭 "직전"(아직 취향이 안 바뀐) 순서를 그대로 저장한다.

### 소피 코드리뷰 반영(PR #49, 2026-11-20)

- **P1-1(affinity 서버 동기화 경합)**: 기존엔 스냅샷을 쓸 때 그 시점의 `ordered`(affinity 기반)
  값을 썼는데, `hydrateTaste`가 아직 서버 동기화 전일 수 있어 경합이 있었다. → 애초에 affinity
  값 자체를 안 쓰고 "클릭 직전 화면에 보이던 순서"만 기록하도록 바꿔 경합을 제거.
- **P1-2(세션 전체 고정)**: 기존엔 `ordered`가 바뀔 때마다 effect가 계속 다시 써서, 한 번
  스냅샷이 생기면 탭을 닫을 때까지 순서가 영구 고정됐다. → "쓰기 1회(떠날 때) + 읽기·삭제 1회
  (돌아올 때)"로 바꿔 한 번의 왕복에만 적용되게 함.

## Verification

- Playwright로 재현: 홈 로드 → (히어로 임계값 안정화를 위한 워밍업 1회 왕복) → 피드 순서 기록 →
  카드 클릭(상세 이동, `recordView` 발생) → 뒤로가기 → 순서 다시 기록 → 1차·2차 왕복 모두 일치.
- 복귀 후 `sessionStorage`의 `moodfit:home-order`가 비어있음(소비 후 삭제) 확인.
- `tsc --noEmit`, `npm run build` 통과.
