# 경쟁 분석 & 전략 강화 — Kiko / 룩핀 vs 무드핏

작성 2026-07-22 · 시장조사 + 포지셔닝 대비 + 무기 우선순위

## 0. 시장조사 (정직한 결과)

- **"Kiko" 남성 패션 앱**: 공개 웹에서 특정 불가. 잡히는 건 **키키코(KIKIKO)=10대 여성 쇼핑몰**(무관). → Kiko는 스텔스/신규로 추정. **본 문서는 Kiko를 전략문서 §0.5 서술 기준**(위쪽 시장·패퍼 언어·"인당 5,000개 태깅"·전문가 큐레이션·AI가 패퍼 취향 학습)으로만 다룬다. 사실 미확인.
- **검증된 실물 경쟁사 = 룩핀(Lookpin, Mozzet)**: 650만~1000만 남성 코디앱. 확인된 기능:
  - 맞춤 코디 추천(4만여 코디), **체형 기반 추천**(내 체형 유사 모델 코디)
  - **AI 큐레이션**(핀/장바구니/구매 학습 → 개인 맞춤)
  - **'옷장'**(내 옷 등록 → 어울리는 코디·상품 추천)
- **의미**: 우리가 "다음"이라 여긴 기능(체형·옷장·개인화 추천)을 **룩핀은 이미 대규모로 운영 중**. → 기능으로 경쟁하면 흡수당한다. 해자는 기능이 아니어야 한다.

## 1. 우리 서비스 (현 빌드 기준)

- 일상어 검색 → 무드 사진 그리드(6축 벡터) → **길게 눌러 해설**("왜 멋있는지" 반말) → 사진 탭 → 상세(완성가·자연 번역기·통째로 담기·판매처 병기) → 3회 저장 → **추구미 카드**("전체의 X%") → **"이 추구미로 다시 보기"(개인화 출입구)** → 나의 공간(추구미 프로필·무드 지도·내 방·내 옷).
- 데이터: photos.mood_vector + caption(해설), 저장·클릭 affinity, 검색 로그. Supabase 연결.

## 2. 포지셔닝 대비 (핵심 축)

| 축 | 룩핀(실물) / Kiko(위쪽 큐레이션) | 무드핏 |
|---|---|---|
| **문턱 위치** | 위쪽 — 이미 관심 있고 "코디를 고르러" 온 층 | **아래쪽 — 관심은 있는데 실행 못 하는 문맹** (§0.5 문턱 원칙) |
| **관계** | 가르침·추천("이렇게 입어라", 4만 코디 중 골라줌) | **번역("이래서 멋있어")** — 안 가르치고 답만(제0조) |
| **입력** | 상품/코디 브라우징, 필터, 핀 | **일상어·아무말**("꾸안꾸") — 언어 없이 냄 |
| **정체성** | 상품/코디 카탈로그 + 개인화 추천 | **"내 추구미만 모아두는 곳"(장소화)** |
| **데이터 해자** | 코디 태깅 + 구매/핀 로그 | **일상어→선택사진 무드 벡터**(문맹의 언어사전, 겹4) |
| **감정** | 동경(잘 입는 코디를 따라) | **복구("취향 없는 게 아니라 이름을 몰랐을 뿐")** |

## 3. 룩핀이 겹치는 지점 = 경고 (정면 경쟁 금지)

룩핀은 이미 **체형 추천·옷장·AI 큐레이션·코디 추천**을 보유. 우리가 같은 프레임으로 가면 규모(650만+)·데이터에서 진다.

- ❌ "코디 추천 정확도", "4만 코디", "체형 맞춤 추천"으로 경쟁 → 룩핀 우위 영역.
- ⭕ **같은 기능이라도 프레임을 바꾼다**: 
  - 룩핀 '옷장'(등록·관리) → 우리 **'내 옷'**은 관리 도구가 아니라 **무드경 구매의 자동 아카이브 + "이거 들어간 룩 보기"**(소유 결).
  - 룩핀 '체형 추천' → 우리 **'내 체형으로 보기'**는 추천이 아니라 **AI 스트릿샷 인물을 내 체형으로 재현**(v1.5, 구조적 유일).
  - 룩핀 '코디 추천' → 우리는 추천이 아니라 **"왜 멋있는지 해설"** + 예산 재구성(자연 번역기).
- **원칙: 기능이 겹쳐도 프레임(번역·추구미·복구)이 다르면 다른 제품이다. 룩핀의 언어(추천·코디·큐레이션·랭킹)를 우리 UI에서 쓰지 않는다.**

## 4. 무기로 삼을 차별화 — 3개로 압축

룩핀·Kiko가 **구조적으로 흉내내기 어려운** 것만 남긴다:

1. **해설 = 관계 차별 (최우선 무기).** "왜 멋있는지"를 반말로 번역 → 룩핀(추천)·Kiko(패퍼 큐레이션) 어디에도 없음. 이게 "가르치지 않고 답을 주는" 유일 포지션. → **1급 시민으로**(상세 상시 노출·그리드 첫 카드 밴드, 이미 착수).
2. **무드 벡터 취향사전 = 데이터 해자(겹4).** "일상어 → 실제 고른 사진"의 매칭은 우리만 쌓인다. 룩핀은 코디·구매 로그(상품 축), 우리는 **언어↔시각 무드 축**. Kiko가 패퍼 언어를 학습할수록 패퍼에 최적화되고 문맹에서 멀어짐(§0.5 축3). → **검색·선택 로깅을 최우선 자산으로 계측**.
3. **살 수 있는 무드보드 = 실행 완결.** 핀터레스트(저장만)와 룩핀(코디→개별 상품) 사이. 완성가·통째로 담기·판매처 병기로 "그 사진 그대로" 산다. → products 시딩으로 완결(진행 중).

## 5. 전략 강화 (액션)

- **문턱 사수**: Kiko/룩핀이 "위쪽 관심층"을 먹는 동안 **"아래쪽 문맹"을 선점**. 카피·기능 전부 "설명 못 해도 눈에만 있으면 사게" 문장으로 필터.
- **언어 위생**: UI·마케팅에서 **추천/코디/큐레이션/랭킹/베스트** 금지(룩핀 언어). **번역·이름 붙이기·추구미·왜 멋있는지** 유지.
- **무기 순서로 리소스 배분**: ① 해설 전면화·품질 ② 무드 벡터 로깅/개인화 ③ 실행 완결(products). 체형·옷장·코디정확도는 후순위(룩핀 영역).
- **한 줄 대외 포지셔닝**: *"룩핀은 4만 코디 중 골라주고, 무드핏은 네 말에 이름을 붙여 네 걸 만든다."*
- **검증 지표**: 해설 펼침률(무기1), time-to-추구미카드(문턱), 무드 벡터 축적/재검색 개인화 체감(해자).
